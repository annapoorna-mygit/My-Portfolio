NGSM Infrastructure Inventory

Unified Compute-Node & Management-Switch Collection @ HPE

Project Overview

Infrastructure inventory needs to describe both compute nodes and the management switches that connect them. A node-only collection model makes it difficult to select, collect, and report on those different device types through one workflow. I built a Python inventory service and extended its node collection with Aruba management-switch support, carrying that model through the CLI, API, collection, and query layers.

My Role: End-to-end implementation and validation of inventory workflows, from device collection and CMDB-driven events to operator-facing results, with QE coordination and peer guidance.

One Collection Model for Nodes & Switches

Adding switches meant more than adding a collector. The surrounding services also needed to stop assuming every collection target was a node.

  • Aruba Collection: Implemented a management-switch collector and parsers alongside the existing node collectors
  • Mixed-Target Selection: Extended CLI and API target selection so a collection can include nodes, switches, or both
  • Collection & Query Services: Carried mixed-target support through collection execution and inventory queries, rather than creating an isolated switch-only path
  • Target-Based Results: Generalized totals and failure reporting from node-specific fields to a common target model, with corresponding CLI output and tests

Event-Driven Inventory Workflows

Collection is part of an ongoing inventory lifecycle. I own CMDB-driven handling for add, delete, and modify events, connecting infrastructure changes to inventory jobs and a configuration management database (CMDB).

  • Implemented asynchronous inventory-to-CMDB posting
  • Handled single- and multi-node events and corrected automatic inventory-job creation
  • Worked with QE on test scenarios and integration validation across the inventory workflow

Efficient Execution, Consistent Operator Experience

I improved the node-collection execution path while keeping compatibility and unavailable nodes in view. The same attention to unnecessary work applies to the CLI that operators use to inspect collections.

  • Batched Node Collection: Migrated remote execution to ClusterShell batching, with node-availability checks and a PDSH fallback
  • Leaner CLI Requests: Removed a redundant log-summary lookup from collection-details output, saving one API call per invocation
  • Tested Output: Updated collection-command and detail-command tests to reflect target-based results and the simplified output
What This Enables: A shared collection and query workflow for compute and management-network inventory, with totals and failures reported consistently for either device type.
